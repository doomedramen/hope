## Fixed scope and decisions

- Independent product for up to 250 hosts. Rust Axum/Tokio/SQLx SQLite server; Rust agent; shared versioned protocol. Next.js App Router static export, shadcn/ui, Tailwind semantic tokens, shadcn/Recharts charts. Rust serves the export; production requires no Node process.
- One administrator, protected first-run setup. Canonical HTTPS server origin behind an existing reverse proxy. Custom CA support must retain certificate verification.
- Linux server host networking is the primary discovery deployment. Docker Desktop must report reduced capabilities. Linux/macOS agents, x86_64/ARM64, systemd/launchd only for the first release.
- CIDRs get fair concurrent discovery, independently bounded enrichment, cancellation, and visible progress. Agents report their own machine, not remote networks. Unanswered probes do not prove a host is offline.
- Map modes: topology, subnets, health. Show provenance for observed, inferred, and manual relationships; never fabricate physical switch connections. Preserve selection and filters across map/list changes.
- Reports every 30 seconds with jitter; inventory on enrollment, change, and periodic refresh. Explicit unavailable values, stable identity, bounded buffering, separate revocable credentials. Raw history 24 hours; five-minute aggregates through day seven.
- Manual and SSH installation share one signed installer workflow. Enrollment tokens: 15-minute expiry, one identity per token, hashed storage. Downloads precede execution. Confirm installation only after the installed service sends an accepted report.
- Defer Windows, distributed discovery, switch integrations, notifications, and multiple accounts. Do not add these while closing current gaps.

### Ticket 08 — SSH installation jobs

Implemented in `crates/hope-server/src/ssh.rs`, migration `0003_install_jobs.sql`, protocol types (`InstallJob` extended; `InstallStage`, `InstallMode` added; `web/lib/protocol.ts` regenerated with `make types`) and `web/components/install-dialog.tsx`.

- **Trust:** fingerprint discovery (`POST /ssh/fingerprint`) never authenticates. A job is bound to the selected host id, address, port and confirmed fingerprint; `check_server_key` refuses a different key during key exchange, so no authentication material is sent (`HOST_KEY_MISMATCH`). Private keys are decoded before connecting, so a wrong passphrase makes no connection (`KEY_INVALID`). Passwords, keys and passphrases are held in `Zeroizing` strings and dropped after authentication; russh receives its own copy of a password, which cannot be zeroized from here.
- **Progress protocol:** only `hope-install: phase=<known>`, `hope-install: error=<KNOWN_CODE>` (text after the code discarded) and exact known `notice=` strings are parsed; all other lines, over-long lines (1 KiB), lines with control bytes and output beyond 1 MiB total are discarded or end the job (`OUTPUT_LIMIT`). User-facing messages and retry guidance come from a server-side catalog; a unit test checks every `fail`/`err` code in `install-agent.sh` is catalogued. Remote output and tokens are not persisted or logged (the job logs only id, status and code).
- **Timeouts and states:** defaults are connect 15 s, inactivity 5 min (reset by any received output byte), total 20 min, report wait 2 min. They are adjustable through `ssh::set_limits` (tests only). Statuses: `completed`; `failed` for failures with confirmed meaning (rejected credentials, host key, key, remote error code, first-report timeout); `uncertain` for connection loss, inactivity/total timeout, output limit, exit without a recognized code, exit 0 without `complete`, `INTERRUPTED`, `ROLLBACK_INCOMPLETE`; `interrupted` for jobs left running at server startup. Uncertain messages never claim rollback.
- **Success criteria:** installer exit 0, a `complete` phase and no error code, plus server-side evidence polled from the database. Reinstall (host already has an agent): the agent bound at job creation has an unrevoked identity and its `last_report` is newer than the time the installer first reported replacing the service (`place-binary` or later, after the old service was stopped); a token consumed by a different agent gives `IDENTITY_MISMATCH`; the new token need not be consumed. Fresh install: the job's token was consumed by an agent whose accepted report is newer than that boundary. No change to the agent or report schema; the activation UUID check stays inside the installer (`status --activation-id`).
- **Persistence/API:** table `install_jobs` stores host id, address, port, fingerprint, username, mode, status, stage list, error code, vetted message, notice, agent ids and timestamps. History is capped at 100 jobs / 30 days, at most four run concurrently. `GET /ssh/jobs` and new `GET /ssh/jobs/{id}`. The UI reopens a running job, lists previous jobs for the host, shows stages, vetted message/notice and per-code guidance, and retry pre-fills address/port/username but requires fresh fingerprint confirmation.
- **Sudo/CA:** the command is the existing `install_command` shape, sent on stdin to `sh -s`; the installer uses `sudo -n` only (no password is piped) and falls back to a user service, which surfaces as a vetted notice. `HOPE_CA_CERT`/`--cacert` handling is unchanged. `State::open_with_agent_ca` lets tests set the CA path without environment mutation.

### `update` migrates containers built with the first pair, 2026-10-16

A container installed by the first community-scripts pair (binary in `/opt/hope/bin`, console in `/opt/hope/web`, releases in `/opt/hope/releases`, unit `ExecStart=/opt/hope/bin/hope-server`) broke on its first `update` with the branch-tracking script: `fetch_and_deploy_gh_branch` replaced `/opt/hope` with the checkout, the unit's binary disappeared, `hope.service` failed and Caddy answered 502. `update_script` now detects that unit line before the branch check and migrates: stops the service, copies releases to `/var/lib/hope/releases` and the old binary to `/usr/local/bin`, rewrites `HOPE_WEB_DIR` and `HOPE_RELEASE_DIR` in `/etc/hope/hope.env` (adding `HOPE_SETUP_TOKEN` when missing), writes the current unit, reloads systemd and removes `/root/.hope` so the branch is deployed and built. Containers that already ran the broken update are in the same state (the old unit line is still there) and are repaired by running `update` again. The structural tests check the migration precedes the branch check and that the migrated unit equals the installed one.

### Change the administrator password from the console, 2026-10-16

### Agent packages out of the box, and agent versions

The console reported "No signed agent packages are available" on every Proxmox install, because publishing agents needed a signing key and a manual `assemble-release.sh` run. The build release now also carries `hope-agents.tar.gz` (unsigned agents for all four platforms, built by the reusable `build-agent.yml` at the build's version), and the server package carries `tools/assemble-release.sh`. `install/hope-install.sh` creates `/etc/hope/release-signing.pem` for that server and signs the agents into `/var/lib/hope/releases`; `ct/hope.sh` re-signs on every `update` with the existing key (or creates one for a converted container) and keeps the previous release if signing fails. The CI publish job proves the bundle signs with a throwaway key before releasing.

Versions: `server-build.yml` computes `<major>.<minor>.<run>` once and passes it as `HOPE_BUILD_VERSION` to the server package and the agents; the agent compiles it in (`option_env!`, falling back to the crate version for local builds) and sends it as `User-Agent: hope-agent/<version>`. The server stores it on the host (`Host.agent_version`, set on enrollment and on accepted reports, ignored unless it is a short `[A-Za-z0-9.+-]` string), and `Bootstrap.agent_release` / `ReleaseAvailability.version` name the signed release on offer. The console's `agentUpdate()` compares the two numerically and shows an Update agent notice in host details. Tests: `agents::tests::agent_versions_come_only_from_well_formed_user_agents`, `reports_record_the_agent_version_and_bootstrap_names_the_release_on_offer` (API), a fleet unit test and a Chromium test. Not done: automatic agent self-update (deliberately), and the host installer (`scripts/install-hope.sh`) still needs agents published by hand.
